# โปรแกรมโรงแรม — เลือกพนักงาน และ UC01–UC10

โปรแกรมทำงานครบตั้งแต่ค้นหาห้อง จอง ข้อมูลผู้พัก เช็คอิน รับเงิน Folio/อ้างอิงใบเสร็จ เช็คเอาต์ สถานะห้อง และรายงานแล้ว ใช้ Java 21, Spring Boot 3.5.16, JdbcTemplate, Thymeleaf และ MySQL 8.4.13 โปรแกรมกับฐานข้อมูลเปิดเฉพาะ `127.0.0.1` บนคอมเครื่องเดียว

รีโปนี้เก็บตัวแอป สคริปต์เปิดใช้งาน ซอร์สโค้ด การทดสอบ และเอกสารประกอบ ส่วนรายงาน/Drawio ของวิชา SA แยกจากรีโปแอป

เริ่มจากโคลนรีโป แล้วเปิด PowerShell ในโฟลเดอร์แอป:

```powershell
git clone https://github.com/Phongwasit/SA-Hotel-App.git
cd SA-Hotel-App
```

ต้องมี Java 21, Maven และ Python 3.12 ที่เรียกด้วย `py -3.12` บน Windows โดยตั้ง `JAVA_HOME` และให้ `mvn` อยู่ใน PATH ครั้งแรกต้องใช้อินเทอร์เน็ต สคริปต์จะเตรียม MySQL และพนักงานสามคนใน `.runtime` ของเครื่องนั้น ไม่ได้ดาวน์โหลดฐานข้อมูลหรือรหัสผ่านจากเครื่องผู้จัดทำ

## เปิดใช้งาน

เปิด PowerShell ในโฟลเดอร์นี้แล้วรัน:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Start-Hotel.ps1
```

จากนั้นเปิด **http://127.0.0.1:8080** เลือก `reception1`, `reception2` หรือ `reception3` ได้เลย ไม่ต้องกรอกรหัสผ่าน ทั้งสามคนทำงานได้เหมือนกัน ระบบเก็บผู้ทำรายการตามคนที่เลือก เปลี่ยนคนได้ด้วยปุ่ม “เปลี่ยนพนักงาน” มุมขวาบน

การเลือกพนักงานใช้สำหรับระบุคนทำรายการบนคอมพิวเตอร์หน้างาน ไม่ต้องยืนยันรหัสผ่าน รหัสพนักงานและประวัติเดิมยังอยู่ครบ การเปิดโปรแกรมซ้ำเพิ่มเฉพาะพนักงานที่ยังไม่มี ไม่เขียนทับคนเดิม

ครั้งแรกต้องมี Java 21, Maven และ Python ที่เรียกด้วย `py -3.12` พร้อมอินเทอร์เน็ตสำหรับดาวน์โหลด dependencies กับ MySQL ZIP จากผู้ผลิต หลังดาวน์โหลดและสร้าง JAR แล้ว การเปิดใช้งานปกติใช้ไฟล์ในเครื่อง ไม่มีฟอนต์หรือ CDN ภายนอก

## ทดลองอะไรได้แล้ว

1. เลือกพนักงานจากสามคนโดยไม่ใช้รหัสผ่าน เปลี่ยนคนทำงานได้ และต้องเลือกพนักงานก่อนเปิดหน้าทำรายการ
2. เลือก Standard, Deluxe หรือ Suite ระบุวันเริ่มพัก วันออก และจำนวนห้อง
3. ดูรายการห้องที่ว่างตลอดช่วงที่เลือก จำนวนห้องที่พบ และจำนวนที่ยังขาด
4. เปลี่ยนเงื่อนไขแล้วค้นหาใหม่ โปรแกรมอ่านฐานข้อมูลใหม่ทุกรอบ
5. ตรวจข้อความเมื่อกรอกวันหรือจำนวนห้องไม่ถูกต้อง เมื่อไม่พบห้อง และเมื่อโหลดฐานข้อมูลไม่ได้
6. เลือกหลายห้องจากผล UC01 แล้วสร้างการจองด้วยชื่อผู้จองและเบอร์โทร
7. ค้นหาการจองด้วยรหัส ชื่อ หรือเบอร์โทร เปิดดูรายละเอียด และแก้ไขชื่อ ห้อง หรือคืนพัก
8. เพิ่มห้องหรือลดห้องผ่าน “แก้ไข” ห้องที่ลดออกเก็บเป็น CANCELLED ไม่ลบรายการเดิม
9. เลือก “ยกเลิกทั้งหมด” เมื่อไม่เข้าพักเลย ถ้ามีห้องเช็คอินแล้วจะยกเลิกทั้งหมดไม่ได้ การแก้ไขคงห้องที่เช็คอินแล้วไว้

ข้อมูลห้องตรงที่ยืนยันไว้: Standard 27 ห้อง ราคา 800 บาท, Deluxe 12 ห้อง ราคา 1,000 บาท และ Suite 2606/2608 ราคา 1,100 บาท เตียงใหญ่ 1 เตียงมีเฉพาะ 1402, 1404, 2606 และ 2608 ทุกห้องพักได้สองคน

**ฐานสาธิตเริ่มจากไม่มีการจองหรือการพัก และตั้งสภาพห้องเริ่มต้นเป็น VACANT/CLEAN/USABLE เพื่อทดสอบโปรแกรม** ข้อมูลสภาพห้องนี้ยังไม่ใช่ผลสำรวจหน้างานจริง ไม่มีข้อมูลแขกหรือการรับเงินจริงถูกนำมาใส่

งาน UC03–UC10 เปิดใช้งานแล้ว ดู [คู่มือครบวงจร](docs/USER_GUIDE.md) และ [ตารางผลทดสอบทั้ง 10 UC](docs/ACCEPTANCE_RESULTS.md) การค้นหา UC01 ไม่ได้กันห้อง ต้องยืนยันบันทึก UC02 หรือเช็คอินจริง UC04 ก่อน

UC02 เก็บภาพก่อนเปลี่ยนแปลงทั้ง EDIT และ CANCEL ผู้รับจองเดิมไม่เปลี่ยนเมื่อพนักงานคนอื่นมาแก้ไข ส่วนรหัสพนักงานที่ทำการแก้ไขอยู่ในข้อมูลประกอบประวัติ บันทึกและอ่านกลับใน transaction เดียว ถ้าขั้นใดล้มเหลวจะย้อนกลับทั้งหมด

## ลำดับ UC01 ที่คงตามแบบ

`RoomListController` อ่าน `queryUC01_1` ผ่าน JdbcTemplate แล้วเรียก `RoomCollection.storeRoomList(availableRooms)` ก่อนแสดงช่องค้นหา เมื่อกดค้นหา จะโหลดและ store ใหม่ก่อนตรวจเงื่อนไข ค้นใน Collection แล้วแสดงผล

`RoomCollection` เป็นข้อมูลของรอบคำขอนั้น ไม่มี Singleton หรือรายการห้องเก่าที่เก็บข้ามคำขอ ส่วน SQL อ่านห้อง ราคา ประเภท และช่วง BOOKED/ACTIVE แล้วตัวจัดกลุ่มรวมแถวตาม room_id เป็นห้องเดียว

ช่วงวันทับกันเมื่อ `existingCheckIn < checkOutDate AND existingCheckOut > checkInDate` จึงรับวันพักต่อกันได้ รายการ CANCELLED ไม่กั้นห้อง รายการ CHECKED_IN ใช้ ACTIVE stay แทน ห้อง OUT_OF_ORDER ไม่อยู่ในผลค้นหา แต่ห้องที่มีผู้พักหรือรอทำความสะอาดวันนี้อาจว่างในอนาคตได้ ต้องตรวจความพร้อมจริงอีกครั้งใน UC04

วันที่ส่งจากปฏิทินเป็นรูปแบบ ISO ภายในระบบ ผลค้นหาแสดงวัน/เดือน/ปี ค.ศ. รูปแบบตัวช่องปฏิทินขึ้นอยู่กับภาษาของเบราว์เซอร์ ส่วน MySQL/JDBC ใช้ UTC+07:00 และการหาวันปัจจุบันใน Java ใช้ Asia/Bangkok

## ฐานข้อมูลและการเปิดซ้ำ

- มีตารางธุรกิจตามแบบ **16 ตาราง / 83 ฟิลด์ / 22 ความสัมพันธ์ FK** พร้อม 41 ห้องจริง
- `flyway_schema_history` เป็นตารางเทคนิคของตัวจัดการ migration เพิ่มจากตารางธุรกิจ ไม่ใช่ entity หรือ UC ใหม่
- `V1` สร้างโครงสร้าง และ `V2` ใส่ประเภทกับเลขห้อง เมื่อเปิดซ้ำ Flyway ตรวจเวอร์ชัน ไม่ล้างฐานหรือเติมห้องซ้ำ
- ฐานใช้งานชื่อ `hotel_frontdesk` ส่วนทดสอบใช้ `hotel_frontdesk_test` คนละฐานกัน
- คีย์คู่ของ allocation กันอ้างคืนของอีก stay หรือวิธีชำระของอีก payment และ UNIQUE(charge_id) กันการจ่ายคืนเดิมซ้ำ ส่วน UC05 ล็อกและตรวจคืนที่ยังไม่จ่าย อ่านยอดเต็มคืนจากฐาน และรวมยอดแต่ละวิธีก่อนบันทึกแล้ว
- ห้ามแก้ V1/V2 ที่ใช้ไปแล้วเพื่อเปลี่ยน schema รอบต่อไปให้สร้าง V3 หรือ migration ใหม่

MySQL ไม่ได้ติดตั้งเป็น Windows service และไม่แก้ฐานข้อมูลเดิมของเครื่อง ไฟล์โปรแกรมฐานข้อมูล ข้อมูลจริงที่บันทึก รหัสผ่าน และ cache อยู่ใน `.runtime` ห้ามลบโฟลเดอร์นี้ถ้าต้องการเก็บข้อมูลเดิม และอย่าส่งต่อทั้งโฟลเดอร์พร้อม source โดยไม่ตรวจข้อมูลก่อน

ถ้าจะสำรองทั้งชุด ให้หยุดโปรแกรมกับฐานข้อมูลก่อน แล้วคัดลอก `.runtime/mysql-data` และ `.runtime/local-settings.json` ไปเก็บในที่ปลอดภัย ไฟล์ตั้งค่านี้จำเป็นสำหรับเข้าใช้ฐานเดิม ไม่ต้องคัดลอก `.runtime/m2` ที่เป็น cache dependencies

## ปิดโปรแกรมและสร้างใหม่

ปิดเฉพาะเว็บแอป:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Stop-Hotel.ps1
```

ปิดฐานข้อมูลด้วย:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Stop-Hotel.ps1 -IncludeDatabase
```

หลังแก้โค้ด ให้หยุดแอปก่อน แล้วสร้างและเปิดใหม่:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Start-Hotel.ps1 -Rebuild
```

สคริปต์ตรวจพอร์ต 8080 ก่อนสร้าง JAR ถ้าพอร์ตยังถูกใช้อยู่จะหยุดให้ไปปิดแอปก่อน เพื่อไม่เขียนทับ JAR ที่ Windows กำลังใช้งาน

## ผลทดสอบ

รันการทดสอบกับ MySQL แยกไว้ได้ด้วย:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Test-Hotel.ps1
```

หลักฐานรอบก่อนปรับหน้าตาผ่าน **71 กรณี MySQL/JDBC/MVC/Security** และ **37 จุดตรวจ Chrome** (Login/UC01 9 + การจอง 8 + ครบวงจร 20) มี [ตารางผลทดสอบ 10 UC](docs/ACCEPTANCE_RESULTS.md), [ผลรวมที่อ่านด้วยโปรแกรม](docs/verification-summary.json), [บันทึกการเปลี่ยนแปลง](docs/IMPLEMENTATION_LOG.md) และ [ภาพจากโปรแกรมจริง](docs/screenshots)

`Test-Hotel.ps1` ใช้ Maven JVM แยกจากเว็บแอปและฐาน hotel_frontdesk_test โดยไม่สร้าง Surefire JVM ซ้อนบน Windows เครื่องนี้ ตัวเรียกใช้ `py` แบบซ่อนหน้าต่างและรอ Java จริงจนจบ ตรวจ exit code จริง ไม่ถือว่ามีไฟล์ XML เก่าแล้วผ่าน

การทดสอบที่สร้าง/แก้/ยกเลิก/เช็คอิน/รับเงิน/ออกเอกสารใช้ฐานทดสอบ ตรวจยอด 3,200 บาทจากสี่คืน รับเงินสองครั้ง เงินสด 1,600 บาท และเชื่อมใบเสร็จหนึ่งใบกับสองการพัก/สองเงินรับแล้ว ก่อนลบเฉพาะข้อมูลสมมติของตัวทดสอบ ฐานใช้งานยังไม่มีรายการแขกหรือรับเงินจริงจากการทดสอบนี้

ผลทดสอบล่าสุดวันที่ 7 พฤศจิกายน 2569 ผ่าน 98 integration tests บนฐานทดสอบ รวมการเลือกพนักงานทั้งสามคนแล้วบันทึกการจองลงรหัสพนักงานถูกคน และตรวจ Chrome ทั้งตัวทดสอบ/ตัวใช้งานจริง ครบหน้าเลือกสามขนาดจอ การเปลี่ยนพนักงาน และเมนู 12 หน้า ภาพและ JSON หลักฐานเดิมที่แนบใน docs เป็นรอบก่อนปรับหน้าตา ไม่ใช่ภาพล่าสุดทุกหน้า

สคริปต์ `tools/browser_*.cjs` เป็นเครื่องมือเก็บหลักฐานรอบเดิม ยังใช้แบบฟอร์ม login เก่าและตำแหน่ง Puppeteer/Chrome ของเครื่องเดิม หากจะรันต้องปรับให้ใช้หน้าเลือกพนักงานและตำแหน่งบนเครื่องนั้นก่อน ส่วน `record_*_status.py` และ `create_initial_schema.py` เป็นเครื่องมือภายในที่อ้างชุดเอกสารต้นทาง ไม่จำเป็นต่อการเปิดแอป ห้ามใช้สร้างทับ migration ที่ใช้งานแล้ว

## แหล่งอ้างอิงเครื่องมือ

[ข้อกำหนด Spring Boot 3.5](https://docs.spring.io/spring-boot/3.5/system-requirements.html) รองรับ Java 21 และ Maven ที่ใช้ในเครื่อง ส่วน MySQL ใช้ [ZIP ทางการ](https://dev.mysql.com/downloads/mysql/8.4.html?os=3) โดยตรวจ checksum ก่อนแตกไฟล์ การกำหนดเขตเวลา JDBC แบบ offset อ้าง [เอกสาร Connector/J](https://dev.mysql.com/doc/connector-j/en/connector-j-connp-props-datetime-types-processing.html) เพื่อใช้ +07:00 ได้แม้ MySQL ยังไม่ได้ลงตารางชื่อเขตเวลา


อัปเดต 7 พฤศจิกายน 2569: หน้าค้นหาห้องเก็บห้องที่ติ๊กไว้ข้าม Standard/Deluxe/Suite ในแถบห้องที่เลือกจนไปหน้าจอง เปลี่ยนวันพักแล้วต้องค้นหาและเลือกใหม่ ตรวจห้องว่างจากฐานข้อมูลใหม่ก่อนส่งต่อและก่อนยืนยันบันทึก ไม่กันห้องตั้งแต่ติ๊กเลือก ช่องชื่อบุคคลไม่รับตัวเลข ส่วนชื่อหน่วยงานมีเลขได้แต่ต้องมีตัวอักษร ตรวจหน้าเว็บและฝั่งบันทึก ผลทดสอบล่าสุด95เคสผ่านทั้งหมด พร้อม Chrome แบบเปิด/ปิด JavaScript

หน้าสถานะห้องอัปเดตข้อมูลจากฐานข้อมูลทุก 10 วินาทีโดยไม่โหลดทั้งหน้า คงตัวกรอง ห้องที่เลือก และค่าที่ยังไม่บันทึก กดรีเฟรชเองได้ หากข้อมูลเปลี่ยนระหว่างกรอกจะแสดงข้อมูลล่าสุดให้ตรวจสอบ ปรับข้อความเวลาเข้าพักให้อ่านง่ายแล้ว ผลรวมล่าสุด98เคสผ่าน พร้อมตรวจ Chrome ทั้งตัวทดสอบและตัวใช้งานจริง
